## 4. 完成内容

把预置硬删除 Service 与 e2e 对齐 API_CONTRACT v2.3 / DATABASE_SCHEMA v2 逻辑删除口径：

1. `items.service.ts remove()`：物理删除（`items.remove`）→ 逻辑删除
   `UPDATE items SET deleted_at = now() WHERE id = :id AND user_id = :userId AND deleted_at IS NULL`；
   命中 → 204；未命中（不存在 / 他人 / 已删除）→ 404 NOT_FOUND（**v2.3 最终口径：重复删除 = 404**，未采用 M1-001 交接单 §64 旧说法"重复删除仍 204"）。
2. 全部 items 查询显式过滤 `deleted_at IS NULL`：
   - `list()`：`where { userId, deletedAt: IsNull() }`（列表不含已删）
   - `findOwned()`：`where { id, userId, deletedAt: IsNull() }`（getById / update / RecordsService 的 records 入口全部经此过滤，已删玩物的详情/PATCH/records 一律 404）
3. 删除带 records 的玩物成功（204），item_records / record_images 物理保留（e2e + curl 实测）。
4. 未新增恢复/回收站功能；未改契约、entities、migrations、uploads 模块。
