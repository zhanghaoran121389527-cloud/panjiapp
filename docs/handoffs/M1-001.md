## 【Migration】

- 迁移拆分（DATABASE_SCHEMA §8）：① CreateTables（6 表 + 2 索引 + 唯一约束 + CHECK + deleted_at）② SeedCategories（幂等）。
- 依据 §8 注释"**M1-001 尚未实施，本 v2 变更随首版迁移一次落地，无增量迁移**"：旧迁移文件删除、首版迁移重写（未伪造历史，也未产生增量迁移）。
- 回滚路径验证：`migration:revert` 倒序成功（先 Seed 删 5 品类，再 drop 6 表），随后 `migration:run` 完整重建成功（本机验证输出见 §测试结果）。

## 【最终Schema】

与 `docs/DATABASE_SCHEMA.md` v2 参考 DDL **逐字段一致**（本机 PG16.14 实际 inspection 结果）：

- 6 表：users / auth_identities / categories / items / item_records / record_images（+ TypeORM 自带 migrations 表，无任何 M2 表）
- items：`deleted_at timestamptz NULL`（NULL=在用；非 NULL=已删除）
- FK：auth_identities→users **CASCADE**；items→users **RESTRICT**；items→categories **RESTRICT**；item_records→items **RESTRICT**；record_images→item_records **CASCADE**
- 唯一约束：`uq_auth_identities_provider_identifier`、`categories.name`、`uq_record_images_record_sort`
- 索引：`idx_items_user_id`、`idx_item_records_item_id`
- CHECK：nickname 1~20、name 1~50、content 1~500、duration_minutes 1~1440、method 1~20、sort_order ≥0
- 时间戳/日期/命名/uuid 约定均符合 §0

## 【逻辑删除实现】

（M1-001 职责边界：**本任务只落 schema**；以下语义为 DATABASE_SCHEMA v2 定义，服务实现随 M1-003）

- 字段：`items.deleted_at timestamptz`（NULL=在用，非 NULL=已删除，UTC）
- 默认查询排除：是——所有 items 查询须显式 `deleted_at IS NULL`（§9.7，禁 ORM 隐式软删）
- owner 获取已删除 item：否——已删除玩物对外一律 404，记录不可达但物理保留
- item_records / record_images：保留（item_records FK RESTRICT 防物理误删；已实测物理 DELETE 被拒）
- DELETE API 数据库变化（M1-003 实施）：`UPDATE items SET deleted_at = now() WHERE id=? AND user_id=? AND deleted_at IS NULL`，响应 204，重复删除仍 204
- M1 无恢复/回收站接口（不自行发明）

- 未 seed 用户/帖子/点赞/商品等任何演示数据。Dev Login 测试用户按需运行时创建（M1-002）。
