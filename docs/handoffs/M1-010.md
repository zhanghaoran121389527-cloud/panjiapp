## 1. 完成内容

- **记录页**（`Features/Records/RecordView.swift`，替换 RecordPlaceholderView，全屏 sheet「记录今天」+ 左上 ✕）：
  - **默认表单只有三样**（验收①）：照片 3 列网格（首/尾为添加格 accentSoft+camera，PhotosPicker 多选 0~N，选择顺序=展示顺序）+ 一句话（多行，占位「今天怎么样？」，打开即聚焦，1~500 截断）+ 底部「保存」。
  - **更多记录项**（默认折叠，0.2s 动画）：记录日期（DatePicker 上限=北京时间今天，未来灰置，过去=补录，验收⑤；**未动日期不传 recordedDate 走服务端默认，动过则传所选值**，线框 06）/ 盘玩时长（Stepper 0~1440 步进 5，0=「未记录」→ null）/ 盘玩方式（≤20 截断）。
  - **保存流程**：按选择顺序逐张上传（photoUrls 下标顺序=上传顺序，验收③）→ 全部就绪才 POST 3.11；**失败张置灰 + 行内提示「这张没传成功，点按重试」→ 点击该张单独重传**，其余已成功 URL 不重传（08-states D）；无照片可直接保存（验收②）；防连点=提交中禁用（验收⑥）；保存失败全部内容保留、重试只补未完成步骤。
  - **成功闭环**：保存成功 → dismiss sheet → 详情页 toast「已保存」（checkmark.circle.fill + 1.5s 自动消失，DS §6.8）+ success 触感反馈（`sensoryFeedback`）→ `onDismiss` 自动回刷详情时间轴（M1-009 已接线，验收④：补录日期自动归位由服务端排序保证）。
  - **放弃确认**：有未保存内容时 ✕ 弹「放弃这次记录？」（放弃/继续编辑）。
- **网络层**：`APIDTOs` 追加 `CreateRecordRequest`（photoUrls/content/durationMinutes/method/recordedDate，全按契约 camelCase 与 null 规则）/`RecordResponse`。

## 4. 使用 API（契约 v2.3）

| 接口 | 用途 |
|---|---|
| `POST /v1/uploads` | 每张照片（multipart `file`，Bearer；MIME 文件头推断；顺序上传） |

## 9. 异常状态

| 场景 | 表现 |
|---|---|
| 照片上传失败（超 10MB/格式/网络） | 对应格子置灰 + 行内「这张没传成功，点按重试」；点击该格单独重传；不阻塞加选其他照片 |
| 保存失败 | 主按钮上方 danger 行（文案走 08-states B 表）；内容/照片/日期/时长全部保留；重试只补剩余步骤 |
| 401 | 清 token 回登录 |
| 未保存内容点 ✕ | 系统确认「放弃这次记录？」 |
