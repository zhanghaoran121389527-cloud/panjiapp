## 1. 完成内容

- **编辑玩物**（复用 M1-008 表单，线框 07）：详情页「编辑」→ 全屏 sheet「编辑玩物」，表单与创建页完全同构并**全部预填**（名称/品类/封面当前值/子类/入手日期/尺寸/备注）；**更多信息有已填项时默认展开**；**无变化时「保存」禁用**（hasChanges 全字段比对）；编辑页不自动聚焦；保存 = 换封面先上传 → `PATCH /v1/items/:id`（整单重发等价实现"只发变化字段"：未动字段回传原值、清空选填显式 null——契约 3.8 合法；已向总控申报该实现口径）；成功 toast「已保存」→ 关 sheet → 详情 onDismiss 回刷（验收①：详情与收藏柜同步——收藏柜由返回链路 onChange 回刷）。
- **删除玩物**（线框 07/DS §6.9）：编辑页底部「删除玩物」危险文字按钮 → 系统 `confirmationDialog`（标题「删除“X”？」、消息「它的全部记录和照片会一起删除，无法恢复。」、删除 destructive 红/取消）→ `DELETE /v1/items/:id`（204 逻辑删除）→ **关闭编辑页并返回收藏柜（详情一并弹出）**，列表 onChange 回刷后玩物消失（验收②③）；删除失败 → toast「删除失败，请重试」停留本页，内容保留。
- **404 处理（验收④）**：对已删除玩物的 PATCH/DELETE → `NOT_FOUND` 映射：编辑保存失败显示「内容不存在或已被删除」（行内 danger）；删除失败 toast 同文案；用户关闭后详情 onDismiss 回刷 → 详情 notFound 态「这件玩物不存在或已被删除」→ 返回收藏柜并回刷。全链路无崩溃、有明确提示。
- **时区工具收敛**（总控要求顺带项）：新增 `Features/Items/BeijingDate.swift`（endOfToday/todayDate/string(from:)/date(from:)）；`CreateItemStore`/`RecordStore` 各自的北京时间静态工具**全部移除**，统一引用 BeijingDate（RecordView/CreateItemView 的 DatePicker 上限同步改引用）——QA M1-010 观察项闭环。
- **网络层**：`APIClient` 新增 `delete(path:token:)`（无响应体 204 处理）+ 抽取 `makeURL(path:)`（与 request/upload 共用）。

## 14. 已知问题

1. **PATCH 整单重发**：等价实现「只发变化字段」的行为（未动字段回传原值、清空传 null），契约 3.8 合法；如总控要求严格 diff 请求体可后续改造（需自定义编码，收益低）。
2. 删除确认文案沿用 DS §6.9 原文（「…一起删除，无法恢复。」）；v2.3 逻辑删除后数据物理保留但对外不可见且 M1 无恢复，文案对用户语义仍成立。
3. 编辑模式下「移除」封面→PATCH coverImageUrl:null ✓；「更换」走上传→新相对 URL ✓；不换封面则回传原 URL（合法幂等）。

## 18. QA 关注点

- 验收①：编辑保存后——编辑 sheet onDismiss 回刷详情；返回收藏柜 onChange(showDetail) 回刷列表；dayCount 等由服务端刷新返回，客户端不自算。
- 验收②：删除必须经 confirmationDialog 确认（destructive 红）。
- 验收③：删除成功 → onDeleted → 编辑 sheet 关闭 + 详情 dismiss → 收藏柜 onChange 回刷 → 玩物消失（服务端逻辑删除保证列表不再返回）。
- 验收④：对已删玩物（双端/双账号预置删除后）执行编辑/删除：PATCH/DELETE 404 → 明确文案 + 详情 notFound 态，无崩溃。
