## 13. 已知问题

1. **本机无 Docker**：M0-001 的 docker-compose 无法在本机验证。本机验证使用本地 PG16（zonky 二进制，`D:\panji-pg-bin`，数据 `D:\panji-data`，端口 **5433**，因本机 5432 被预装 PostgreSQL `D:\wzw\.pgsql` 占用）。`apps/api/.env` 已指向 5433。QA 请按 infra/README 在 Docker 机器复核（M0-006 代验 M0-001）。
2. **PNPM 未安装**：看板要求 pnpm，本机仅 npm 可用，命令等价；package-lock.json 已提交。若团队统一 pnpm，需在装有 pnpm 的机器重装并生成 pnpm-lock.yaml。
3. **PG 二进制/数据目录必须纯 ASCII 路径**：中文路径（如 `盘迹APP` 内）会导致 initdb 以 GBK 字节注入 UTF8 服务端失败（本机已实测定位）。dev-db.mjs 默认 `D:\panji-pg-bin`/`D:\panji-data` 并附注释说明。
4. **`process.loadEnvFile` 在 jest vm 环境静默失效**（Node 24 + jest 29 实测）：config.ts 改用手写 .env 解析器，行为确定。
5. **本机沙箱限制**（非仓库问题）：禁 .cmd 启动、禁管道捕获（node 命令须直跑且不带 `2>&1 |`）、禁工作区外写入/以管道 stdio 启动子进程——因此 dev-db / npm install 在本机需要提权执行。其他机器无此限制。
6. **e2e 会重置目标库 public schema**（DROP SCHEMA public CASCADE + 重跑迁移）：开发期数据可丢弃（DBI 口径一致），已写入 README 与 setup-env.ts 注释。
