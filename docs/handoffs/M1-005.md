## 4. 完成内容

核对并确认预置 records 模块与 API_CONTRACT v2.3 §3.11~3.12 / DATABASE_SCHEMA §5/§6 **逐项一致，零逻辑变更**（本轮无代码修改）：

| 契约点 | 实现现状 | 结论 |
|---|---|---|
| 3.11 photoUrls 0~N，落 record_images，sort_order=数组下标 | `create()` 事务内 `photoUrls.map((url,index) → sortOrder:index)` 批量落库；响应 photoUrls 按提交顺序 | ✅ |
| 3.11 content 必填 1~500 字 | DTO `@Length(1,500)` + trim | ✅ |
| 3.11 recordedDate 默认北京今天 | `dto.recordedDate ?? todayBeijing()`（应用层北京今天，非 DB CURRENT_DATE） | ✅ |
| 3.11 过去日期=补录 | 同接口接受过去日期，时间轴按日期归位 | ✅ |
| 3.11 晚于北京今天 → VALIDATION_ERROR（A10） | `recordedDate > todayBeijing()` → 400；格式/非法日期（如 02-30）→ 400 | ✅ |
| 3.12 GET records 排序 | `order: { recordedDate:'DESC', createdAt:'DESC' }` | ✅ |
| 归属校验（他人/已删 404） | 经 `ItemsService.findOwned`（M1-003 已含 `deleted_at IS NULL` 过滤） | ✅ |
| A12 长度：durationMinutes 1~1440、method ≤20 | DTO `@Min(1) @Max(1440)`、`@MaxLength(20)` | ✅ |
| photoUrls 仅接受 /uploads/ 相对 URL | DTO `@Matches(/^\/uploads\/…$/, {each:true})` | ✅ |
| 响应结构 3.11/3.12 | `{record:{id,photoUrls,content,durationMinutes,method,recordedDate,createdAt}}` / `{records:[...]}` | ✅ |
| 不增加记录编辑/删除 | 无（契约 M1 不做） | ✅ |
