# 线框 07 · 编辑玩物 + 删除确认

- 文件：`docs/design/07-edit-delete.md`
- 对应接口：`PATCH /v1/items/:id`（3.8）、`DELETE /v1/items/:id`（3.9）、`POST /v1/uploads`（3.10）
- 实现：M1-011（iOS）

---

【任务编号】M0-004（UI）

【页面目标】

在详情页低成本地修正玩物信息、更换封面，以及（明确确认后）删除玩物。编辑复用创建表单，删除必须二次确认，绝不一键误删。

【用户进入页面的原因】

玩物详情右上角「编辑」。

【信息层级】

1. 表单（与创建页完全同构，全部预填）：封面 → 名称 → 品类 → 更多信息（默认展开显示已填项）。
2. 底部主按钮「保存」。
3. 底部「删除玩物」危险文字按钮（与保存分离，最下方）。

【页面布局】

```
┌────────────────────────────┐
│  ✕         编辑玩物        │  ← 全屏 sheet 导航栏
│  ┌──────────────────────┐  │
│  │      [封面大图]       │  │  ← 已填显示当前封面 +「更换」「移除」
│  └──────────────────────┘  │
```

【主要操作】

「保存」：有变化才可点（无变化禁用）→ 换封面则先上传 → `PATCH /v1/items/:id`（部分更新；「移除」封面传 `coverImageUrl: null`）→ 成功 toast「已保存」→ 关闭，详情与收藏柜同步刷新。

【次要操作】

- 「✕」：关闭；有未保存修改时系统确认（「放弃修改？」放弃/继续编辑）。
- 「删除玩物」：弹系统确认（见下）。

【默认状态】

全部字段预填当前值；「保存」禁用（无变化时）。

【空状态】

不适用。

【加载状态】

「保存」按钮 `ProgressView` + 「保存中…」禁用（防连点）。

【错误状态】

- 同创建页：封面上传失败行内提示；保存失败 `danger` 提示行 + 按钮恢复，内容保留。
- 删除失败：确认框关闭后出现 toast「删除失败，请重试」，停留在本页。

【删除确认（系统 confirmationDialog）】

```
标题：删除“四座楼狮子头”？
消息：它的全部记录和照片会一起删除，无法恢复。
按钮：[ 删除 ]（destructive 红）/ [ 取消 ]
```

- 确认「删除」→ `DELETE` → 成功：关闭编辑页并返回收藏柜（详情页一并弹出），列表刷新，玩物消失（M1-011 验收 ③）；无 toast（结果即列表变化）。
- 「取消」：留在编辑页，无任何变化。

【键盘/手势/iOS交互】

- 与创建页一致：聚焦、return 收起、PhotosPicker 换封面。
- 确认弹窗用系统组件，样式随 iOS 版本，不自定义。
- 编辑页打开不自动聚焦（用户先看后改），首次点字段才弹键盘。

【需要开发注意事项】

- `PATCH` 为部分更新：只发送有变化的字段；清空选填字段时显式传 `null`（契约 3.8 规则）。
- 表单组件与创建页共用（M1-008 产出复用，M1-011 验收 ①）。
- 删除成功后：收藏柜列表与详情缓存都要失效刷新；后端硬删除 + 级联删记录照片（裁决 A16），客户端不保留任何本地缓存副本。
- 编辑成功后详情页的 dayCount 等由刷新接口返回，不自算。

【明确不做】

批量删除、删除二次输入文字确认、归档/恢复、记录单独删除、品类管理、分享。
