# 线框 08 · 全局状态（Loading / Error / 图片失败 / 保存失败）

- 文件：`docs/design/08-states.md`
- 实现：M1-006（网络层错误文案映射）起，各页面按本规范落地

---

【任务编号】M0-004（UI）

【页面目标】

四个全局状态全 App 只用一种表现，用户在任何页面遇到问题，反应都一样：知道发生了什么、能做什么。

【用户进入页面的原因】

任何网络请求进行中/失败、图片加载失败、提交失败的场景（非独立页面，是覆盖在所有页面上的状态规范）。

【信息层级】

状态优先级从弱到强：默认（无状态 UI）→ 骨架/局部 spinner → toast（成功）→ 顶部横幅（刷新失败）→ 行内提示（提交失败）→ 整页错误态（无内容可展示）。同一时刻只显示一种，不叠加。

【页面布局】

- 整页错误态：垂直居中，`accentSoft` 圆底图标（网络=`wifi.slash`，其他=`exclamationmark.triangle`）+ 标题（`heading`）+ 说明（`secondary`，居中，≤2 行）+ 主按钮「重试」（宽 240）。
- 顶部横幅：`dangerSoft` 底 + `danger` 字 `caption`：「刷新失败，下拉重试」，页面内容其下正常滚动。
- 行内提示：主按钮上方一行 `danger` `caption` 文案。
- Toast（成功）：底部悬浮胶囊（`textPrimary` 底 + `background` 字 + `checkmark.circle.fill`），自动 1.5s 消失。

【主要操作】

- 整页错误态「重试」：重新发起当前请求；重试期间整页回到骨架加载。
- 时间轴缩略图加载失败：点该格 = 重试加载该图。
- 提交失败后点主按钮 = 重试提交。

【次要操作】

- 已有内容的页面失败：下拉刷新重试（横幅自动消失）。
- 收藏柜/详情封面加载失败：静默降级为占位，无操作（下拉刷新时自然重试）。

【默认状态】

一切请求成功时，上述任何状态 UI 都不出现（骨架在数据到达后原地淡入内容，不闪白屏）。

【空状态】

全局不适用。无数据页面的空态（收藏柜、详情时间轴）由各页线框定义（`03`、`05`），本规范不重复。

【加载状态】

| 场景 | 表现 |
|---|---|
| 页面首次加载（收藏柜/详情） | 骨架占位：`surface` 色块按最终布局摆放，透明度 0.6→1.0 呼吸动画（1s 循环）；收藏柜 4 卡片、详情 1 大图 + 3 条目。**骨架无文字线条** |
| 按钮提交中 | 按钮禁用 + 内嵌 `ProgressView`（`onAccent` 色）+ 文案「进入中…/保存中…/创建中…/删除中…」 |
| 局部小加载 | 系统 `ProgressView`（`accent` tint），居中 |

- 首次加载超 10s 未返回 = 按错误状态处理（超时）。

【错误状态】

**A. 整页错误 / 顶部横幅**

| 形态 | 使用场景 |
|---|---|
| 整页错误态 | 首次加载失败、无内容可展示 |
| 顶部横幅 | 已有内容后的刷新失败 |

**B. 错误文案映射（网络层统一维护，页面不自己造）**

| 来源 | 文案 |
|---|---|
| 网络不可达 / 超时 | 「网络不太顺畅，请检查后重试」 |
| `AUTH_REQUIRED`（401） | 不显示文案：清 token → 回 Dev Login |
| `VALIDATION_ERROR` | 显示后端 `message` 原文 |
| `NOT_FOUND` | 「内容不存在或已被删除」；详情页场景附带「返回」回收藏柜 |
| `UPLOAD_TOO_LARGE` | 「图片超过 10MB，请换一张」 |
| `UNSUPPORTED_TYPE` | 「暂不支持该图片格式」 |
| `INTERNAL` / 其他 | 「出了点问题，请稍后再试」 |

- 所有错误均不弹系统 `alert` 打断用户（唯一例外：放弃未保存内容的确认）。

**C. 图片失败**

| 位置 | 表现 |
|---|---|
| 收藏柜卡片封面 | 静默降级为首字占位（`accentSoft` + 首字），不显示错误 UI |
| 详情封面大图 | 同左；下拉刷新时重试加载 |
| 时间轴缩略图 | 该格 `surface` 底 + `photo` 图标 + `caption`「加载失败」；点击 = 重试 |
| 创建/编辑/记录页已选图 | 缩略图右上「×」仍可移除；不阻塞提交 |

- 原因不区分 404/断网，统一按此处理（简单优先）。

**D. 保存失败（创建/编辑/记录提交失败）**

| 规则 | 说明 |
|---|---|
| 提示位置 | 主按钮上方一行 `danger` `caption`（原因取 B 表映射），不弹 alert |
| 表单内容 | **全部保留**（文字、已选照片、日期、时长），只恢复按钮可用 |
| 重试 | 点主按钮重试；照片上传失败的只重传失败张，已成功的 URL 不重复上传 |
| 防连点 | 提交中按钮始终禁用（裁决 A14） |

【键盘/手势/iOS交互】

- 错误横幅不拦截手势，页面仍可滚动/下拉。
- 整页错误态「重试」带按压反馈；重试期间整页进入骨架加载。
- Toast 与横幅不并存：toast 优先，横幅出现则 toast 不再弹。

【需要开发注意事项】

- 错误码→文案映射放网络层单点维护（M1-006 产出），页面只消费，禁止散落各页。
- 图片失败重试（时间轴缩略图）用 URL 缓存失效 + 重新请求；收藏柜静默降级不重试。
- 超时默认 10s（可配置），与后端一致。

【明确不做】

全局错误注册页、日志上报、离线缓存队列、失败重试倒计时、弹窗式错误提示、错误插画/表情包。
